---
description: 给出可执行的降本建议（含折算口径）。 / Actionable cost-reduction advice with declared savings basis.
argument-hint: "[会话 id | workspace | all]"
---

用户想要降本建议。调用 MCP 工具 `spend_advisor`（它会顺带取静态上下文构成）。

参数：会话 id 传给 `session_id`；`workspace`/`all` 传给 `scope`；`7d` 之类的值传给 `since`。

呈现规则：
- **按可省金额从大到小**列出。金额相同时按字符量。
- 每条都要把**证据**讲出来（服务器名、字符量、占比、调用次数、文件路径、覆盖率），
  因为建议的价值全在可核对。用户会问"凭什么这么说"。
- **必须沿用每条建议自带的折算口径 `savingKind`**，这是本插件最容易被误读的地方：
  - `tokens-fresh` —— 新进上下文的内容，按实测新增输入单价。这是真金白银。
  - `tokens-cached` —— 被反复重发的上下文，按实测缓存读取单价（实测便宜约 41 倍）。
  - `chars-static` —— 常驻缓存的静态内容，**只有字符与占比，没有金额**。
    **绝不要把这类字符量说成"能省多少钱"**，那会高估约 41 倍。
  - `none` —— 信息性结论，本来就没有可省估算，不要替它编一个。
- 明确区分**实测**（token 数、字符量、调用次数、单价）与**估算**（`savingTokens`）。
  可省量是由已发生开销推算的，不是已经省下的钱。
- 对"从未被调用过的 MCP 服务器"这类结论，要说明这是取舍：关闭它会**影响后续会话能力**，
  且该内容常驻缓存、金额影响很小，主要收益是上下文窗口与长会话余量。
- 若 `findings` 为空，直说没有发现明显浪费，不要为了凑数制造建议。

用户追问某条依据时，进一步调用 `spend_attribution`（工具/文件级 token）或
`spend_context_breakdown`（静态构成与 MCP 细分）给出明细。
